# Trigger-based project growth

Start with the smallest workflow that removes a real failure.

## Level 0 — Lean core

```text
AGENTS.md
.ai/ROLE.md
.ai/PROJECT.md
.ai/WORKFLOW.md
```

Single Main, FAST/STANDARD/HIGH_RISK routing, no persistent team state.

## Level 1 — Durable memory

Add a memory router only after facts are being rediscovered or classification becomes costly. Curator work remains candidate-triggered.

## Level 2 — Runtime adapters

Add Codex, OpenCode/OMO or Claude adapters when those runtimes are actually used. Do not copy one runtime's collaboration model into another.

## Level 3 — Optional coordination

Add team state only after multiple writers, exclusive resources, cross-session state or formal verdict dependency appears. Ordinary spawns remain ephemeral.

## Level 4 — Scientific / long-running

Add scientific evidence, long-run supervisor, stage decisions and artifact handoff only when experiments or long stages need them.

## Upgrade rule

```text
observed failure -> smallest facility -> verify the failure is reduced
```

Do not preinstall workflow ceremony merely because a mature project once needed it.
