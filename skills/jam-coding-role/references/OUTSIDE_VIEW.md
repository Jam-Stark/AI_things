# 局外人的看法

Owner/Planner 在问题反复不收敛、准备显著增加投入、切换路线，或主动需要另一个视角时调用 `outside_view`。这不是每个阶段/提交的强制 reviewer，也不新增审批门。

用 `fork_turns="none"` 开新上下文。先给 Owner 原始目标、近期关键选择、支持与反对证据、失败/未测事项、现实约束和可追溯来源；再给团队当前推荐的位置。避免只给成功摘要，不复用已经参与形成推荐的研究身份。共享 memory 也只是待核对材料。

它回答：“在我最近反复讨论的问题背后，有没有一个更深的问题，是我一直在绕着它走，却没有真正问出来的？”给出依据、会改变的下一步决定和能推翻这个判断的观察。认为现有问题定义已经合适同样有效；不为显得深刻强行反对，不猜心理动机。

保持只读，只提供建议，不改实验/代码/资源。新鲜上下文不等于统计独立；角色 TOML 的 read-only 意图也不等于宿主隔离已验证。输出自然简短，必要时借图帮助理解。调用参考 `templates/OUTSIDE_VIEW_REQUEST_zh.md`。
